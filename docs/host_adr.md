# Synapse ホスト本体実装 — Architecture Decision Record（分離管理）

> プラグイン側（C ABI / ホストラッパー / SDK）の正本は [`synapse_adr.md`](./synapse_adr.md)。
> 本書は**ホスト本体実装**（評価器・キャッシュ機構・スケジューラ・グラフ・型変換挿入・プロファイル等）の
> 決定を分離管理する。当面はプラグインインターフェースの設計・実装を詰める段階のため、本書の多くは
> **「契約はプラグイン側で確定済み、機構の実装はこれから」** の状態にある。

## 位置づけ

- プラグイン側 ADR が **契約（ABI 表面・呼び出し規約）** を確定し、本書はその契約を満たす **機構（実装）** を扱う。
- 境界をまたぐ ADR は、契約面を `synapse_adr.md` に [契約IN] として残し、機構面を本書へ [→ホスト] として置く。
  双方は ADR 番号で相互リンクする（番号は振り直さない）。
- 分類軸・★・語彙はプラグイン側 ADR と共通（[`spec_index.md`](./spec_index.md) 参照）。

## 機構エントリ（プラグイン側 ADR からの OUT 先）

現時点ではいずれも **設計方針はプラグイン側で確定、ホスト機構は未実装/最小** の段階。詳細決定は本体ホスト
クレート着手時にここへ追記する。

- **H-001: 非再帰スタック評価器** ← [ADR-001](./synapse_adr.md)
  pull 型・スタック駆動の評価ループ実装。FFI 再帰なし契約（ADR-001）を満たす。`request↔process` ループ
  （ADR-011）の駆動主体。現状は `synapse-host-mini` が最小の参照実装（編集凍結）。

- **H-002: dirty 伝播キャッシュ機構** ← [ADR-014](./synapse_adr.md)
  キャッシュキー `(frame[, 下流要求])`、状態変更時の下流サブツリー無効化。`mark_dirty` 契約（ADR-014）の
  受け手側。ソケット既定値編集のホスト直接検知もここ。

- **H-003: トポロジカル再 declare 伝播（方式b）** ← [ADR-013](./synapse_adr.md)
  接続型変化を declare 無効化トリガとし、トポロジカル順に再宣言を伝播する。`connected_type`（ABI, 確定IN）を
  使う派生型ノードと、ホスト内部型伝播で無改修の恒等伝播ノードに分かれる。

- **H-004: SHARED/OPAQUE の寿命管理（refcount 運用）** ← [ADR-015](./synapse_adr.md)
  clone/drop vtable 契約（ADR-015）の運用側。アンロード遅延（opaque 値限定 RC）は ADR-025／Open-12 と連動。

- **H-005: アンロードの本体側運用（ModuleId purge／トランザクショナルアンロード）** ← [ADR-025](./synapse_adr.md), Open-12
  記述子 static 化（ADR-025）の前提下で、グローバル登録の purge、進行中 declare/process との排他、
  OPAQUE/SHARED 生存中のアンロード遅延を本体が担う。

- **H-006: オートメーション／タイムライン所有** ← [ADR-017](./synapse_adr.md)
  ソケット既定値（=パラメータ）の保存・配送・自動化。型の `default/serialize`・`save/load`（ABI, 確定IN）を使う。

- **H-007: 並列スケジューラ（軸1・将来 軸2,4）** ← [ADR-019](./synapse_adr.md), [ADR-021](./synapse_adr.md)
  caps 宣言（ABI, 確定IN）を読み、クロスノードタスク並列（軸1）を実行。軸2（インスタンス再入タイリング）・
  軸4（フレーム並列）は caps 宣言のみで実装は後。

- **H-008: モジュールローダ（2フェーズロード／型-型依存違反検知）** ← [ADR-027](./synapse_adr.md), [ADR-028](./synapse_adr.md)
  全モジュールの型登録 → 全モジュールのノード登録の順でロード。型登録フェーズ中の他モジュール型参照を
  違反として検知（ADR-028 は★不可逆制約）。`byte_alignment` の 2 冪検証（ADR-029）もここで実施。

## ホスト取り込み範囲・未設計の機構（Open の OUT 先）

プラグイン側 ADR の Open のうち、ホスト機構に属するもの。いずれも未設計。

- **Salsa 風インクリメンタル計算層** (Open-4)
- **ホスト側型変換／convert ノード自動挿入** (Open-9)
- **canonical 型集合の確定** (Open-10)（型集合自体はプラグイン/ホスト境界の設計判断）
- **ROI/領域の下流→上流伝播** (Open-7)（表現の ABI はプラグイン側、伝播機構はホスト）
- **ホスト取り込み範囲のスコープ**（GPU 抽象・メモリアロケータ・色空間・時間・bbox・I/O・i18n・Undo/Redo・オーディオ基盤） (Open-15)
